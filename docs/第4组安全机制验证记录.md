## 三、发现的问题与修复

### 问题：危险指令硬拦截未接入 Agent 工具执行链

- **现象**（修复前）：`DANGEROUS_ACTIONS`（rm/format/shutdown/dd/mkfs/fdisk）硬拦截只存在于 `SystemCoordinator.orchestrate` 契约路径，Agent 主循环 `run/run_stream` 走的是 `_execute_one` → 确认门 → 工具执行，**危险指令只会触发确认弹窗**（base 档下所有 HIGH 需确认），而非硬拦截。
- **风险**：模型在"清理磁盘"等正常上下文里请求 `shutdown`（实测发生），用户一旦误点「允许」即执行不可逆操作——确认弹窗挡不住"社交工程绕过"。

### 修复内容

1. **`core/coordinator.py`**：`DANGEROUS_ACTIONS` 扩充 Windows/PowerShell 变体：
   ```python
   DANGEROUS_ACTIONS = ("rm ", "format", "shutdown", "dd ", "mkfs", "fdisk",
                        "stop-computer", "restart-computer", "remove-item")
   ```
2. **`core/agent.py`**：`_execute_one` 工具执行入口新增 `_sandbox_guard`——run_command 等带 `cmd/command` 参数的工具若命中危险指令或受保护路径，**绕过确认门直接拒绝**（返回 `{success:false, error:"危险指令: ..."}`）并记审计（`sandbox_check` 事件）；`coordinator.enabled=false` 时保持旧行为不变。

### 安全分层（修复后完整链路）

```
用户指令
  → 模型层：SYSTEM_PROMPT 守则（危险操作先拒绝/确认）
  → SecuritySandbox 第一层：DANGEROUS_ACTIONS / PROTECTED_PATHS 硬拦截（绕过确认门）  ← 新增接入
  → 确认门：base 档所有 HIGH 风险征求用户许可（allowed/denied 二选一）
  → 沙箱执行 + 审计 + RAG 轨迹
```

## 四、单元测试

`tests/test_agent.py` 新增 `TestSandboxGuard` 19 例（全自动档 `confirm_high_risk=False` 下验证硬拦截而非确认门）：

- 参数化 15 个危险指令（rm -rf /、rm -rf ~/Desktop、shutdown -h now、shutdown /s /f /t 0、format c:、dd、mkfs、fdisk、Stop-Computer、Restart-Computer、Remove-Item、del /f /s /q、rd /s /q、diskpart、reg delete）→ 全部返回「危险指令」拒绝
- 正常命令 `echo miniyu` → 不受影响、真实执行成功
- `coordinator.enabled=false` → 普通命令保持旧行为（可正常执行），但**危险指令仍被硬拦截**（不依赖确认门、不依赖 SystemCoordinator）
- 非命令工具（current_directory）→ 不受影响

**回归结果：558 项测试全绿**（539 + 19 新增；本记录为该时点快照，后续新增浏览器视觉定位用例后全量累计至 **583**）。
> 09-11 扩展：危险指令硬拦截由"依赖确认门/依赖 SystemCoordinator"加固为 **任何授权档位（base/advanced/full）+ coordinator 关闭时均硬拦截**——即使 `coordinator.enabled=false`，`_sandbox_guard` 也会构造独立 `SecuritySandbox` 兜底；`DANGEROUS_ACTIONS` 扩充 Windows 变体 `del /f /s`、`rd /s /q`、`diskpart`、`reg delete`。对应 `tests/test_agent.py::TestSandboxGuard` 19 例。

## 五、结论

- 危险操作拦截（rm / format / shutdown 等）**已实现并实测生效**：模型层拒绝 + 沙箱硬拦截 + 确认门三层防护；
- 最低授权（base）下确认门工作正常（上一轮实测 shutdown 弹窗→拒绝后取消）；
- 修复消除了"确认弹窗被误点"的最后一层风险，未引入回归（该时点 558 全绿，后续累计 583 全绿）。

## 六、浏览器会话隔离强化（2026-09-11，工具使用约束）

在 P1 成本优化同期，新增**工具使用层面的沙箱约束**（与危险指令硬拦截互补）：

- **浏览器会话屏障**：`browser_launch/navigate` 后置 `_browser_active`，浏览器任务期间拦截 `click_at / send_text / send_hotkey / activate_window` 这类**全局桌面工具**（只读的 `take_screenshot/list_windows` 放行），返回值明确提示用 `browser_*` 或先 `browser_close`。
- **安全意义**：机器学习在网页任务中误切到桌面全局工具，既破坏上下文稳定，也放大对**用户真实桌面的误操作面**。会话屏障把 Agent 的能力边界收敛到"当前浏览器会话"，从源头减少非预期系统操作，属控制约束（confinement）而非仅提示。
- 回归：全量 **590 项测试全绿**；危险指令硬拦截（`_sandbox_guard`）行为不变。
