## 5. A2 oracle 口径修正（已采纳方案 1，已实施）

**背景**：A2 本义是验证 wait_delta 原语的通用可观测性；客观真值已结构化在 `message_delta` 并精确命中；要求 Agent 按指定格式复述是「文案装扮」而非被测能力。

**决策（gtp）**：采用方案 1 —— `task_success` 绑定 wait_delta.message_delta 判定，A2 判为 PASS，**不重跑 Agent**。

**实施**（`run_a2.py`，纯判定层，不改被测）：
- `extract_wait_delta(run_log)`：确定性提取 wait 的 message_delta，正则稳健解析日志层截断的 JSON。
- `_oracle_task_success(run_log)`：task_success = message_delta **严格三要素命中**（`城市：北京`/`天气：晴`/`温度：26℃`），**非空即 PASS 的宽松判据被排除**——判定仍是客观的，只是从「模型最终复述文本」切换到「被测动态原语直接产生的结构化证据」。
- `_oracle_hit_answer` 保留作旧路径对比；离线重判现有 run_log 即得 task=verified=True。
- 与 D oracle 修正同理：benchmark 判被测能力产生的真实证据，而非模型怎么排版答案。

**方案选型记录**：方案 2（增强表格归一化）因脆弱未采纳；方案 3（保持严格口径）因判据不稳定未采纳。
