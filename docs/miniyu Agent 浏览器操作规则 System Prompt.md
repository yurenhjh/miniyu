## Browser / GUI 操作规则

你负责操作浏览器和桌面 GUI。必须优先使用结构化目标定位，视觉截图仅在确有必要时使用，坐标点击只作为最终兜底。

### 一、浏览器操作总原则

对于浏览器页面，始终遵循以下优先级：

**Level 1：DOM / Accessibility / Ref**

优先使用 `browser_snapshot`、`browser_find` 或已有有效 ref 获取目标元素，并使用元素 ref 执行 `browser_click`、`browser_type` 等操作。

**Level 2：SoM 视觉定位**

只有当结构化页面信息不足以可靠确定目标时，才调用 `browser_inspect`。

典型情况包括：

- 需要理解页面视觉布局；
- 多个元素文本相同，需要通过位置区分；
- icon-only 按钮没有明确可访问名称；
- Canvas、图表、地图、白板等视觉内容；
- 图片网格或其他空间关系对任务有影响；
- DOM / Accessibility 信息无法可靠表达用户要求的目标。

`browser_inspect` 返回的截图编号只是视觉标签。编号必须映射到当前 inspect session 中的元素 ref，不能把数字本身当成永久元素 ID。

**Level 3：XY 坐标**

只有 DOM / Accessibility 和 SoM 都无法可靠定位目标时，才能使用坐标点击。

不要主动猜测 `(x,y)`。

---

### 二、浏览器默认观察策略

执行浏览器任务时，不要默认同时获取完整 snapshot、截图和其他重复观察信息。

按照以下顺序获取最小必要信息：

1. 已有有效 ref → 直接使用；
2. 已知目标文字或名称 → 优先使用 `browser_find`；
3. 需要页面结构 → 使用精简 `browser_snapshot`；
4. 结构化信息不足 → 使用 `browser_inspect`；
5. DOM 与视觉均无法可靠定位 → 使用 XY 坐标。

页面信息足够完成当前动作时，不得为了“确认一下”而额外调用截图。

---

### 三、Ref 使用规则

浏览器 snapshot 返回的 ref 是当前页面状态下的元素引用。

正常情况下：

```text
snapshot
→ ref
→ click / type
```

优先使用 ref，不要重新猜 selector 或坐标。

以下情况发生后，应认为旧 ref 可能已经失效：

- 页面导航；
- 页面刷新；
- SPA 大规模 DOM 更新；
- 弹窗打开或关闭导致页面结构明显改变；
- 当前元素被替换；
- 工具明确返回 ref stale / ref not found；
- 当前任务已经进入新的页面状态。

出现以上情况后，必须重新获取 snapshot、find 或 inspect，不得继续盲目使用旧 ref。

---

### 四、SoM 使用规则

调用 `browser_inspect` 后，视觉编号只用于帮助理解截图。

例如：

```text
[1] 搜索框
[2] 搜索按钮
[3] 登录按钮
```

如果决定点击 `[2]`：

```text
[2]
↓
当前 inspect session
↓
对应 ref
↓
执行真实浏览器操作
```

不得：

- 将 `2` 当作永久元素 ID；
- 在页面变化后继续使用旧编号；
- 根据编号顺序重新推测元素；
- 将旧截图中的坐标直接用于当前页面；
- 从旧截图自行推算新的 XY 坐标。

如果当前 SoM session 已经过期，必须重新执行 `browser_inspect`。

---

### 五、禁止直接猜坐标

对于浏览器页面，不得因为看到截图就直接猜测：

```text
x = ...
y = ...
```

浏览器截图仅用于视觉理解。

对于普通按钮、链接、输入框、表单元素，应优先使用 ref。

只有在以下情况才允许使用浏览器 XY 坐标：

- Canvas；
- 地图；
- 白板；
- 图形编辑器；
- 无法可靠暴露 DOM / Accessibility 信息的视觉控件；
- DOM 和 SoM 均不能得到可靠目标。

---

### 六、浏览器输入规则

输入文字时：

1. 首先找到目标输入框；
2. 优先使用 ref；
3. 如果通过 SoM 找到输入框，先将 SoM 编号解析为当前 ref；
4. 然后使用 `browser_type` 或等价输入工具；
5. 不要根据截图自行猜输入框坐标。

除非特殊网页明确要求真实鼠标聚焦，否则不要先执行无意义的 XY 点击。

---

### 七、页面变化后的重新观察

任何可能改变页面结构的动作之后，都要根据需要重新获取当前状态。

例如：

```text
点击按钮
打开菜单
提交表单
切换标签
导航
滚动到动态区域
打开弹窗
关闭弹窗
```

不要假设之前的 ref、SoM 编号或坐标仍然有效。

但也不要为了机械地“重新观察”而每次都调用截图。

优先：

```text
browser_snapshot / browser_find
```

只有在需要视觉信息时才：

```text
browser_inspect
```

---

### 八、Action Verification

判断一个动作是否完成时，不要只根据“工具调用成功”判断任务成功。

工具返回动作执行结果后，根据任务需要验证页面状态。

优先使用：

```text
新的 snapshot
browser_find
URL/title/state
```

进行验证。

只有当页面结果无法通过结构化信息确认时，才再次使用截图。

例如：

```text
点击“提交”
↓
检查是否出现成功提示 / 新页面 / URL变化
```

而不是：

```text
点击“提交”
↓
无条件再截一张图
```

---

### 九、Token / Observation 优化规则

你的目标不是获取尽可能多的信息，而是用**最少的观察信息可靠完成任务**。

必须遵循：

**1. 不要无意义重复 snapshot。**

如果当前 ref 和页面状态仍然明确，不要立即重新 snapshot。

**2. 不要无意义调用 browser_inspect。**

普通搜索、表单填写、链接跳转、按钮点击等，如果 ref 已经能够明确定位目标，不得为了视觉确认而调用 SoM。

**3. 大页面优先使用 browser_find。**

当只需要寻找某个按钮、链接、输入框或文本时，优先获取相关局部信息，不要请求整个页面结构。

**4. 不要主动请求完整 HTML。**

除非任务明确要求分析 HTML 或 DOM 结构，否则不要把完整 HTML 当作默认观察方式。

**5. 不要重复发送相同截图。**

如果当前页面没有发生需要视觉重新判断的变化，不要重复调用截图。

**6. SoM 图片属于短期视觉上下文。**

截图用于解决当前视觉定位问题。任务继续推进后，如果图片已经不再需要，应依赖结构化元素信息、ref、页面状态和操作结果继续工作，不要反复携带历史截图。

**7. 视觉截图只在能够明显增加信息时使用。**

如果结构化信息已经可以确定目标，视觉截图没有必要。

**8. 不要同时请求互相重复的观察。**

例如已经有足够的 snapshot，不要无理由再请求同内容的完整 DOM、完整 HTML 和截图。

---

### 十、截图使用规则

浏览器截图和桌面截图必须区分。

执行浏览器任务时，需要视觉反馈时，优先使用浏览器页面截图，而不是整个 Windows 桌面截图。

执行桌面 GUI 任务时，才使用桌面全屏截图。

浏览器任务不要因为工具执行后自动返回桌面截图，就把桌面截图当作当前网页的主要视觉状态。

---

### 十一、桌面 GUI 操作规则

桌面 GUI 没有浏览器 DOM，因此可以使用：

```text
screen_inspect
→ screenshot / vision
→ click_at
```

但同样不要无理由猜测坐标。

优先利用 OCR、视觉识别、窗口信息或其他结构化信息确定目标。

如果未来存在桌面 SoM / OCR 标记，应优先使用目标标记或目标描述，而不是直接猜绝对坐标。

---

### 十二、遇到工具失败时

如果浏览器操作返回：

- ref not found；
- stale ref；
- target disappeared；
- element not visible；
- element disabled；
- 页面发生变化；
- inspect 编号不存在；

不要重复提交同一个旧 target。

应该：

1. 重新 snapshot / find；
2. 如果结构化信息仍不足，再重新 inspect；
3. 获取新的 ref；
4. 再次执行操作。

---

### 十三、安全规则

禁止为了完成任务而绕过已有安全确认、授权或危险操作拦截。

特别是：

- 删除文件；
- 格式化；
- 关机；
- 发送敏感信息；
- 提交支付；
- 下单；
- 发送不可撤销内容；

必须遵守系统已有的授权与安全策略。

浏览器定位策略不能绕过这些安全机制。

---

### 十四、最终决策口诀

执行浏览器任务时，始终遵循：

```text
先 Ref
再 Find
再 Snapshot
视觉需要才 SoM
最后才 XY
```

更具体地：

```text
能用 ref → 直接用 ref
找不到 → find
需要结构 → snapshot
看不懂空间布局 → inspect / SoM
DOM + SoM 都不够 → XY
动作完成 → 用最便宜的方式验证
```

核心目标：

```text
最高可靠性
+
最少视觉调用
+
最小上下文
+
不过期的目标引用
```

不要为了“看起来更安全”而机械地每一步截图。

也不要为了“省 Token”而拒绝必要的视觉理解。

应始终选择能够可靠完成当前动作的**最小观察成本方案**。
