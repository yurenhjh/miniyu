# 重写 app_send_message：从 Ctrl+F 键盘路线改为"点击 + 探针 + 可选 OCR 门"

桌面版 QQ 是自绘 UI。最初的 `app_send_message` 走键盘路线
（`Ctrl+F` 打开搜索 → 输入关键词 → `Enter` 选中 → 输入消息 → `Enter` 发送），
真机验证时发现 **`Ctrl+F`/`Enter` 焦点会落在联系人"资料卡"而非搜索结果**，
导致进不了目标会话——该键盘路线在真实 QQ 上不成立，记录里曾经的
"真实 QQ 验证成功"实为当时未充分核实的误报。

决策要点：

- **搜索框与聊天输入框都用"探针扫描"定位**，不依赖固定坐标、不依赖视觉：
  清空剪贴板 → `click_at(x,y)` → 粘贴探针串 → `Ctrl+A` → 清空剪贴板 →
  `Ctrl+C` → 读回。只有焦点真的落在文本框、`Ctrl+C` 真实复制到时，
  剪贴板才含探针串——"粘贴源本身就把探针放进剪贴板"因此不产生假阳性。
- **命中即清场**：探针确认命中后立刻 `Ctrl+A` + `Delete` 清掉刚贴进框里的
  探针串再返回。否则文本框残留 `G4probe…`，后续再拼真实关键词让 QQ 拿整串
  去搜索——早期一次真机测试的"搜到"其实靠目标会话恰好已打开被顶到顶部，
  是碰运气而非真命中（探针串污染 bug，2026-09-05 修复，OCR 复验搜索框仅含
  目标关键词）。
- **点选搜索结果行由调用方注入 `verify(screenshot)->bool` 把关**：
  每点一行截一张图，交给视觉/OCR 比对聊天标题与目标关键词，命中才允许继续发送；
  5 行内不命中即报错、零发送。
  把"识别哪个会话是对的"留在 Agent 层（视觉归 Agent），技能本身保持纯确定性。
  > 注（2026-09-06 更新）：OCR 识别默认已迁为**项目内视觉桥** `core.vision_bridge`
  > （读 config.yaml 的 `vision_bridge` 段；主对话 llm 有视觉 `supports_vision=true` 时
  > 直接由主模型看图，见 ADR 0009 / 编排设计决策 10）。最初真机用外部 node 脚本
  > qwen-vision 裁标题横带识别，该通道保留为显式 `vision_js`/`AGENT_VISION_JS` 的旧路。
- **所需坐标以窗口矩形为锚按比例换算**（`get_window_rect` 新增原子能力），
  窗口位置/分辨率变化不失效。
- **新增两个控制器原子能力**：`read_clipboard()`（剪贴板读回）与
  `get_window_rect()`（窗口屏幕矩形），以及公开 `set_clipboard()`。
  三者都不是对外工具（工具数仍为 47），供技能/示例的内部编排使用。
- **发送仍走 Ctrl+A 覆盖 → 剪贴板粘贴 → Enter**（中文安全），保留原返回契约
  `{window, search_keyword, message, screenshot}` 并新增
  `search_box / input_box / verify_result` 字段。

已知局限：

- 一旦某行把会话切入（点错行），下拉列表会关闭，同一轮内无法继续采样更下面的
  候选行；需重新聚焦搜索框再试。因此 `verify` 首选应命中靠前的行。
- 不同 IM 的搜索框/输入框比例位置可能不同，目前内置 `qq_classic` 布局模板，
  其它布局可新增 `_layout_profile` 条目适配。
