## 三、重点测试覆盖明细

### 3.1 ToolRegistry（core/tool_registry.py）

- **注册管理**：注册、别名（`move_file`≡`move_path`）、注销、未注册工具调用 → `{success:false,error}`
- **文件/文件夹操作**：copy/move/rename/delete、create/delete/list、sort_directory、index_files、manage_archive
- **文本/批量/查找**：read/write/edit_file、batch_copy/move、search_files、search_in_files、find_* 
- **磁盘/图片/系统**：disk_usage、get_image_metadata、current_directory、run_command（正常与失败）
- **异常处理**：缺少参数、非法参数、工具抛异常 → 归一为 `{success:false,error}`
- **调用统计**：`get_stats()` 空统计、累计次数（by_tool 排序）、结果记录、清空
- **工具签名**：注册后生成 SHA256 签名、`list_tool_signatures`、完整性校验匹配/不匹配

### 3.2 SkillLibrary（core/skill_library.py，26 技能）

- 信息查询类：`system_info` 返回结构化系统信息
- 文件整理类：`organize_downloads`（演示场景 6）、`smart_organize`、`cleanup_temp`、`cleanup_by_type`、`deduplicate_files`
- 回收站/备份类：`trash_file`、`restore_file`、`empty_trash`、`safe_delete`、`backup_file`、`restore_backup`
- 搜索/索引类：`search_file`、`rebuild_index`、`query_index`、`duplicate_finder`
- 动态注册：运行时注册自定义技能并调用

### 3.3 Mock（mock/mock_tools.py，61 工具全量）

- `MockToolRegistry` 与正式版同名/同参/同返回，内存实现不改磁盘
- `MockSkillLibrary`、`MockOSServiceAPI` 三件套全覆盖
- 异常路径：未知工具/未知技能/缺参

### 3.4 Agent 端到端（工具驱动）

- function-calling 驱动的多步工具调用（真实 LLM 联调见《联调与集成报告》）
- 工具结果截断（超长输出省 token）、循环上限、错误回喂重试

**追加（P1 成本优化，2026-09-11 晚，token 性能归因后落地）**：

| 能力 | 实现位置 | 说明 |
|------|---------|------|
| Observation 生命周期（历史图片裁剪） | `agent._trim_history_images` + `_MAX_HISTORY_IMAGES=2` | 发往 LLM 的历史最多保留最近 2 张观测截图，更旧的图片从载荷剥离、文字保留；对话持久记录/产物目录仍存全量。化解"旧图逐轮重发"这一 token 膨胀主因。 |
| 结构化优于自动截图（P1-B） | `agent._browser_action_needs_visual` + 两处截图门控 | 成功的 snapshot/find/type/wait/read 不再自动截图；仅 launch/navigate、click 引起页面/URL 变化、以及失败诊断时才截。桌面全局操作保留保底截图。 |
| 结构化读文字守则 | System Prompt 第 14 条 | 读回复/数字/状态一律走 `browser_read_text`/snapshot，不靠截图视觉；并约束避免"先试 A 不行再试 B"式冗长自我复述以减少思考 token。 |
| 新增回归测试 | `tests/test_agent_obs.py`（7 项） | 覆盖历史图片裁剪边界、cap=0 关闭、视觉判定（结构化不截 / launch / click 状态变化 / 桌面保底）。 |

**实测依据**（豆包任务 `run_log_*.jsonl`）：单张观测图=2466 token 且随图片数严格线性累加，末轮 6 张图占输入约 50%；旧图剔除 + 成功不自动截图两招叠加，可在不损失功能前提下把简单网页任务的图片数从 6 压到接近 0~1。
