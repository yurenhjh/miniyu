## 二、真机联调证据

### 2.1 真实 LLM 驱动文件系统工具（阿里云百炼）

- **环境**：阿里云 DashScope compatible-mode，模型 `qwen3.5-plus`，function-calling 真实生效。
- **成果**：真实 LLM 自主规划并连续调用 `list_directory → read_text_file → copy/move → run_command` 完成多步文件操作，全程零人工干预。
- **证据**：`docs/evidence/agent_qwen_live.md`（含真实调用链）。

### 2.2 邮件技能联调（SMTP + IMAP 闭环）

- **成果**：`send_email` 组合技能 SMTP 发送 + IMAP 回读**到达收件箱**核验闭环，验证了"外发副作用工具"在真机的可用性与可核验性。
- **证据**：`docs/evidence/email_live_qq.md`。

### 2.3 QQ 通信技能联调（Windows 桌面）

- **成果**：`read_qq_chat` / `app_send_message` 经屏幕 OCR 核对会话标题后读写聊天，组合技能"一步到位"而非零散点击。
- **证据**：`docs/evidence/qq_group_一中兄弟会_*.png` + `evidence/README.md`。

### 2.4 百炼服务端工具（联网搜索 / 代码解释器）

- **联网搜索**：`enable_search` 服务端搜索，云端返回带参考来源，实测模型可据此作答。
- **代码解释器**：纯计算回合自动启用，实测 `qwen3.7-flash`/`qwen3.5-plus` 精确计算 **123²¹**，模型不支持时自动探测停用。
- **证据**：`examples/probe_bailian_code_interpreter.py` + 配置注释。

## 四、集成数据流正确性检查

```
第4组输出接口 tool_result_json：
{"success":true, "result":"...", "tool":"<name>", "elapsed_ms":N, "ts":"..."}
```
- 与设计书第 4 组契约、MCP `CallToolResult` 对齐；错误统一 `{success:false,error}`；
- 与安全（第 5 组）协同：删除/外发类操作前置确认；与 RAG（第 5 组）：审计时间戳与执行轨迹入库。

### 4.1 与第 5 组（系统协调+安全+RAG）的集成验证（09-09 补齐）

对照设计书第 5 组职责，本轮新增 `core/coordinator.py` 并与 Agent 打通，验证数据流闭环：

| 第 5 组职责 | 集成验证 | 结果 |
|------------|---------|------|
| SystemCoordinator 编排 | `register/orchestrate` 按 1→5→2→3→4 数据流，审计+RAG 存储 | ✅ 27 项测试全绿 |
| SecuritySandbox 四层安全 | 权限检查(危险指令/受保护路径) → 沙箱执行 → 签名验证(SHA256) → 隐私保护(脱敏) | ✅ 危险操作拦截 + 隐私脱敏测试通过 |
| RAGKnowledgeBase 向量检索 | 存储「用户输入→动作→结果」，词频向量+余弦相似度召回 | ✅ 检索相关性测试通过 |
| 审计日志 | JSON Lines 可落盘、线程安全、事后查询 | ✅ 持久化测试通过 |
| 降级 Mock | MockCoordinator 基于 57 同构工具 Mock 跑端到端编排 | ✅ 测试通过 |

**Agent 集成**：`agent.run / run_stream` 每次对话结束自动记录一条审计（`agent_turn`）+ 存一条 RAG 轨迹；`agent.coordinator.enabled` 可关（默认开）。这使「工具调用（第 4 组）→ 审计/RAG（第 5 组）」成为运行时闭环，数据流正确性由测试保障。

### 4.2 安全机制实测 + 危险指令硬拦截（09-11 浏览器验证）

- **实测环境**：Web 界面（真实 LLM qwen3.7-flash），授权档位调至**最低档 base（基础授权）**。
- **实测结果**：`rm -rf /`、`format` → 直接拒绝；`shutdown` 修复前仅弹确认窗（截图 `security_test_3`）、**修复后直接拒绝、无确认弹窗**（截图 `security_test_6`）；正常操作（列出目录）不受影响。
- **发现并修复**：`DANGEROUS_ACTIONS` 硬拦截原先只在 `SystemCoordinator.orchestrate` 契约路径，未接入 Agent 工具执行链 → 新增 `core/agent.py::_sandbox_guard` 接入 `_execute_one`，带 cmd/command 参数的工具命中危险指令**绕过确认门直接拒绝**（杜绝确认弹窗被误点的社交工程绕过）；`DANGEROUS_ACTIONS` 扩充 Windows/PowerShell 变体。
- **回归**：新增 `TestSandboxGuard` 13 例，全量 **552 全绿**；记录见 `docs/第4组安全机制验证记录.md`。
